Short definitions of the terms used throughout the modding docs, in alphabetical order, each with the page to read next.

## Terms

| Term                 | Meaning                                                                                                                                                                                                                           |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`.luma`**          | A packaged mod: one zip file holding `luma.json`, content layers, built code and media. Players install this file. See [The .luma format](reference/luma-format.md).                                                              |
| **after** (hook)     | A hook that runs after the game's function and can change its `result`. See [Hooks](lumascript/hooks.md).                                                                                                                         |
| **assets**           | A mod's own new files (models, textures, sounds, effects) in `layers/<layer>/assets/`, named by mod path.                                                                                                                         |
| **before** (hook)    | A hook that runs before the game's function and can `skip` it.                                                                                                                                                                    |
| **build**            | Compiling a mod's LumaScript and C into one native library per platform, with `lumalink build`.                                                                                                                                   |
| **code consent**     | The player's answer to "allow this mod's code?", asked once per mod (and again when its code changes). See [Permissions](start/permissions.md).                                                                                   |
| **conflict**         | A mod listed in `conflicts`, which must not be on together with yours.                                                                                                                                                            |
| **content**          | Everything a mod brings that isn't code: models, animations, materials, effects, sound, screens, fonts, stages and table patches. See [Content overview](content/overview.md).                                                    |
| **cook**             | Preparing a mod's content for the player's device and graphics. It happens on the player's machine when the game starts with the mod. A mod whose content fails to cook is off for that session.                                  |
| **Error** (finding)  | A finding that refuses a mod, switches it off, or means something it meant to do didn't happen. Compare **Note**.                                                                                                                 |
| **event**            | The answer to something that waits on the outside world (a file read, a network reply), delivered to the mod at the start of a frame. Handled with `on <service>.<event>` or `wait`ed in a task.                                  |
| **Exchange folder**  | A folder that the player and other mods can open. Reading and writing it needs the `fs.exchange` permission.                                                                                                                      |
| **extra library**    | A native library a mod brings besides its own (a platform SDK, a physics library), listed in `code.libraries`. Needs the `native` permission.                                                                                     |
| **finding**          | One problem reported by the validator: a code, a level (Error or Note), the mod, the file and place, and what was expected.                                                                                                       |
| **format**           | The version of the `.luma` format a mod is written for, `"1.0"` today, given in `luma.json`.                                                                                                                                      |
| **game path**        | A file's path on the game's disc, such as `ObjectData/Kuribo.arc`. A file inside an archive is `ObjectData/Kuribo.arc/Kuribo.bdl`.                                                                                                |
| **game.pak**         | Your imported game: Nebula's copy of your game disc. LumaLink reads it with `--game`.                                                                                                                                             |
| **guard**            | The part of the game that catches a crash in a mod's native code, switches that mod off for the session and lets the game go on. See [Debugging](start/debugging.md).                                                             |
| **handle**           | A `ref<C>`: a safe reference to a game object that may be gone. `get()` gives the object or `none`. See [The game in scope](lumascript/game-objects.md).                                                                          |
| **hook**             | Code of yours that runs when the game calls one of its functions: `before`, `after`, `wrap` or `replace`.                                                                                                                         |
| **id**               | A mod's permanent name for programs, such as `gold-flower`: 3 to 64 lowercase letters, digits, `-` and `.`.                                                                                                                       |
| **kit data**         | Data for a library mod such as LumaKit, in `kit/<module>/*.json`, checked against the module's schema.                                                                                                                            |
| **L-code**           | A validator code, such as `L203`. `lumalink explain` says what one means. See [Error codes](reference/error-codes.md).                                                                                                            |
| **layer**            | A folder of content under `layers/<name>/`, applied in the order `luma.json` lists. A layer can have a `when` condition (an option, region, language, platform or the mod's code).                                                |
| **library mod**      | A mod that other mods `use`, such as LumaKit. Mods that use it list it in `needs`.                                                                                                                                                |
| **load order**       | The order of the Mods list, top first. Hooks run in this order, and when two mods change the same thing, the one higher in the list wins.                                                                                         |
| **log**              | `log "..."` in LumaScript writes a line to the game's log as your mod.                                                                                                                                                            |
| **LumaCore**         | The interface the game gives every mod's library, defined in `luma.h`. LumaScript uses it for you.                                                                                                                                |
| **LumaKit**          | The library mod of ready-made gameplay building blocks (forms, items, actors, HUD, menus, cameras...), used with `use kit.<module>`. See [LumaKit overview](lumakit/overview.md).                                                 |
| **LumaLink**         | The command-line tool that creates, checks, builds, packs, runs, tests, lists, extracts and converts mods. See [LumaLink overview](lumalink/overview.md).                                                                         |
| **LumaScript**       | The language mods are written in, in `.lum` files, compiled to native code. See [LumaScript at a glance](lumascript/overview.md).                                                                                                 |
| **`luma.h`**         | The C header that defines how a mod's library talks to the game. It's in the SDK folder (`LUMA_INCLUDE`).                                                                                                                         |
| **`luma.json`**      | A mod's manifest: its id, version, name, regions, options, permissions, needs, layers and code. See [luma.json](reference/luma-json.md).                                                                                          |
| **mod log**          | The in-game record of everything said about each mod this session, shown as notices and on Mods > Log. See [Debugging](start/debugging.md).                                                                                       |
| **mod path**         | The name of one of a mod's own assets. The game knows it as `<id>:<path>`, so it never clashes with another mod's.                                                                                                                |
| **Mods screen**      | The game's screen where players switch mods on and off, order them, set their options and read the mod log.                                                                                                                       |
| **module**           | One LumaScript file. `source/ball/fly.lum` is the module `ball/fly`, and `source/main.lum` (`main`) is the mod's entry.                                                                                                           |
| **names folder**     | The game's description of its functions, types, services and renderer features, which LumaLink checks code against (`--names`).                                                                                                   |
| **native**           | Compiled to machine code for the device. All mod code is native; nothing is interpreted. Also the permission for extra libraries.                                                                                                 |
| **needs**            | The other mods yours requires, each with a version range. Each must be installed, on and loaded first.                                                                                                                            |
| **Note** (finding)   | A finding shown for information: nothing is refused or lost. Compare **Error**.                                                                                                                                                   |
| **not checked**      | A rule LumaLink couldn't run because an input was missing (usually `--names` or `--game`). `pack` refuses until every rule is checked.                                                                                            |
| **option**           | A setting of your mod the player changes on the Mods screen, declared in `luma.json` and read in code with `option <key>: <type>`.                                                                                                |
| **pack**             | Writing a mod folder as a `.luma`, after every rule passes, with `lumalink pack`.                                                                                                                                                 |
| **patch**            | A JSON file in `layers/<layer>/patches/` that sets, adds, removes or selects rows of a game file that has rows, by key. See [Table patches](content/table-patches.md).                                                            |
| **permission**       | Something a mod must declare and the player must allow before the mod can use certain services (`net.internet`, `system.clipboard`...). See [Permissions](start/permissions.md).                                                  |
| **placeholder**      | Stand-in content the game shows when a mod's content can't be found or shown, with an entry in the mod log.                                                                                                                       |
| **platform**         | One of the nine systems mods run on, such as `windows-x64` or `android-arm64`. Code is built for each.                                                                                                                            |
| **proceed**          | In a `wrap`, `proceed()` calls the next wrap and then the game's own function.                                                                                                                                                    |
| **region**           | A release of the game: `RMGE01` (North America), `RMGP01` (Europe), `RMGJ01` (Japan).                                                                                                                                             |
| **reload**           | Replacing a mod's code while the game runs, as `lumalink run` does when you save. Only what the mod `keep`s survives. See [Workflow](start/workflow.md).                                                                          |
| **replace** (hook)   | A hook that takes the place of a game function entirely. Only one mod at a time may replace a given function.                                                                                                                     |
| **S-code**           | A LumaScript code, such as `S0904`: a compile error at build time, or a script error while the game runs.                                                                                                                         |
| **script error**     | A mistake found while the game runs (an index outside a list, an empty handle, division by zero). The statement stops, the error is logged with its file and line, and the mod keeps running.                                     |
| **SDK folder**       | The folder holding `luma.h`, given with `--sdk` or `LUMA_INCLUDE`.                                                                                                                                                                |
| **self-description** | The game's description of itself: every function, field, class, enum, global and service a mod may use. The compiler and validator check mods against it. See [The game's description of itself](lumascript/game-description.md). |
| **service**          | An interface the game gives every mod (input, saves, files, network, audio, time, drawing, UI...), used with `use svc.<name>`. See [Services overview](services/overview.md).                                                     |
| **skip**             | In a `before` hook, `skip` stops the game's function from running (with a result, for a function that returns one).                                                                                                               |
| **start check**      | The checks the game runs at each start with mods: its own parts, consent, the rules that depend on this setup, the cook and the code. A mod passes all of them and is fully on, or it's off with its reasons.                     |
| **state machine**    | `states` in LumaScript: an object's behaviour as named states with `enter`, `update` and `exit`, switched with `go`. See [Tasks, states and wait](lumascript/tasks.md).                                                           |
| **table**            | A game file with rows, such as a `.bcsv`. Tables are changed with patches, never replaced.                                                                                                                                        |
| **task**             | A LumaScript function that can `wait` frames, seconds, a condition or an event, and carry on later. See [Tasks, states and wait](lumascript/tasks.md).                                                                            |
| **test harness**     | The tool that runs a mod's `test game` tests inside the game. See [Writing tests](lumalink/testing.md).                                                                                                                           |
| **validator**        | The rule checker the game and LumaLink share. Every rule has an L-code and a message in each of the game's 14 languages. See [How the validator works](reference/validator.md).                                                   |
| **view**             | A LumaScript value that refers to a game object for the moment, such as `self` in a hook. To keep a reference across frames, turn it into a handle. See [Memory and lifetimes](lumascript/memory.md).                             |
| **wrap** (hook)      | A hook around a game function that can change its arguments and calls `proceed()` at most once.                                                                                                                                   |
